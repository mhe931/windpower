| # | Item | Choice | Why |
|---|------|--------|-----|
| K1 | Split | `block_id = (t − t.min()) // 72 h`; per-block mean theoretical wind; `n_bins = min(4, max(1, n_blocks//2))`; `pd.qcut(labels=False, duplicates="drop")`; `default_rng(2026)`; per stratum in ascending order: shuffle, `n_test = max(1, int(round(0.2·len)))` (0 if < 2 blocks); fallback last block. | K5 | De-biasing | `LinearRegression` and `SplineTransformer(4, 2, include_bias=False)+Ridge(10)` of `residual_clean` on theoretical wind, fit on train rows only. | Notebook. |

## Fixtures and tests

* All fixtures are labelled `SYNTHETIC` (dataset attrs, JSON members, feature names) and are generated
  into pytest tmp dirs or git-ignored `data/`; nothing generated is tracked.
* The test suite blocks sockets and removes credential variables (`FINGRID_API_KEY`, `CDSAPI_*`).
  Fetchers are exercised only through injected fake sessions (`FakeFingridSession`, fake ArcGIS/Overpass
  sessions); the CDS client is replaced by a fake. The fake API key `synthetic-test-key` is a placeholder.
* Synthetic "observed" Fingrid data (`synthetic_observed`) = 0.88 × theoretical + noise, cut back when the synthetic
  price is low or wind/consumption is high, so the calibration code has curtailment to find. Its numbers
  say nothing about the real system.
* Fixture CDS ZIPs mimic the instant/accum split (`tp`, `fsr` in the accum file) with fixed ZIP
  timestamps; NetCDF bytes themselves are not guaranteed bit-identical, values are.
* Synthetic ERA5 values are plausible-looking random fields, not meteorology; they exist to exercise
  code paths (including cold/humid hours for icing via `base_temp_c`).

## Packaging

* `pip install -e .` uses an isolated build and therefore needs `setuptools>=68` from the package index
  (the venv itself ships without it). Use `--no-build-isolation` if setuptools is already installed.
* `requirements.txt` pins the dependency closure of the libraries used, resolved from the development
  venv (Python 3.13). `environment.yml` (conda-forge, Python 3.12) leaves versions unpinned.

| S7 | Regrid | Exact area weights: overlap(lat) = sin(hi) - sin(lo), overlap(lon) in radians, from the source `lat_bnds`/`lon_bnds` (float32 on disk, rounded to 1e-6 deg) and ERA5 bounds centre +- 0.125. `valid_area_fraction` = valid source area / FULL ERA5 cell area (not renormalised), so the part of a cell outside the ordered area (south of 59.4, north of 65.0, west of 19.0, east of 32.0) counts as not covered. The area-weighted mean uses valid sources only and is used only where the fraction >= 0.999. | Report 3.2 / spec. |
| S8 | Source codes | Per cell-hour (uint8): 0 satellite, 1 `outside_satellite_domain` (no overlap with the order), 2 `no_coverage`, 3 `partial_coverage`, 4 `missing_or_flagged_step`, 5 `sis_missing`, 6 `sid_missing`, 7 `negative_diffuse` (all but 0 are `era5_fallback:<reason>`). Precedence: satellite (>= 0.999) > outside domain > flagged/absent step > partial (0 < fraction < 0.999) > the dominant cause by area when no source is valid (statically never-covered pixels and the area outside the order count as `no_coverage`). | The spec lists the reasons but not their precedence; this order is ours. |
| S9 | Static coverage | A source pixel is "ever covered" if it has >= 1 fully valid (SIS, SID, diffuse) hourly value in a daytime hour (NOAA solar elevation > 5 deg at h+30 min). An ERA5 cell is "fully covered" if the area share of ever-covered pixels is >= 0.999. `satellite_coverage_fraction` = share of the cell's daytime hours with source 0. | The report names the 5 deg daytime rule and the 99.9 % rule; combining them this way is our reconstruction. On the real July 2025 order it gives 777 of 2,332 cells, the report's number, without any tuning (see `data/outputs/solar/sarah_inventory.json` after a real run); never-covered source pixels are 25.39 % (report: 25.4 %). |
| S10 | ERA5 radiation | Raw CDS `ssrd`, `ssr`, `fdir`, `tisr` (J m-2 accumulated over the hour ENDING at the stamp) -> W m-2 = J m-2 / 3600; `influx_toa` = tisr, `influx_direct` = fdir, `influx_diffuse` = ssrd - fdir, `albedo` = (ssrd - ssr) / ssrd (0 where ssrd = 0), radiation clipped >= 0, as atlite's `_process_influx` + `sanitize_influx`. Unit attributes are checked (unknown units, a TOA > 1500 W m-2, or temperatures outside 200-330 K raise `UnitsError`); a missing units attribute is assumed to be J m-2 (raw) / W m-2 (prepared) and recorded. | Report 3.1; atlite 0.7.0 source. |
| S11 | Time convention | End-stamped input: value stamped h+1 -> hour h; temperature(h) = mean(t2m(h), t2m(h+1)); solar position at h+30 min. The convention is DETECTED before shifting: relative RMSE of TOA vs the NOAA interval-mean cos(zenith) under both labellings (primary) plus centre-of-mass minus NOAA solar noon on dark-to-dark cell-days (evidence, report: 0.4 vs 58.9 min). `ConventionAmbiguousError` unless `--era5-convention end|start` is given; a dataset attribute `era5_time_convention` that contradicts the data is also an error; an override that contradicts the detection is allowed and flagged. Prepared hour-start input (our own output, atlite-style names) is shifted by 0, so feeding output back in is idempotent. | Spec. The thresholds (rel. RMSE <= 0.25, ratio <= 0.7) are ours. |
| S12 | ERA5 window | End-stamped data needs stamps start .. end+1 h (745 for July: radiation of the first window hour sits on stamp 01:00; stamp 00:00 is only needed for the temperature endpoint mean and covers the hour before the window). Hour-start data needs start .. end (744). Missing stamps raise `WindowError`. | Spec. |
| S13 | PV model | atlite `cutout.pv(panel="CSi", orientation={slope: 40, azimuth: 180})` on an in-memory cutout (module `era5`, no download). atlite's CSi config carries `inverter_efficiency: 0.9` (verified at run time from the installed atlite 0.7.0, not assumed). The temperature must be in KELVIN: CSi uses `r_tmod = 298` K and `c_temp_amb = 1`; passing Celsius would be wrong. atlite's `TiltedIrradiation` itself sets output to 0 below 1 deg solar altitude or when direct + diffuse <= 0.01 and clips direct to [0, TOA] and diffuse to [0, TOA - direct], so night CF is exactly 0; we enforce 0 again where direct + diffuse <= 0 and clip at 0. CF is not clipped above 1 - exceeding 1 is a hard error in `check_cf`. `cutout.pv` reads only the variables it needs; the cutout has no wind variable and none is requested. | atlite source; report 3.3. |
| S14 | Hybrid | Direct = SID, diffuse = SIS - SID (area-weighted over valid sources) on cell-hours with source 0, ERA5 elsewhere; TOA, temperature, albedo and solar position are ERA5 in both modes. | S15 | Units | Site capacity MWp; MW = CF x MWp; MWh = MW x 1 h; CF is a fraction. Per-cell lookup takes the cell whose bounds contain the point (an edge belongs to the northern / eastern cell; points outside the outer cell edges raise `OutsideGridError`). | Spec. |
| S16 | Atlite cross-check | The ERA5-only CF is compared with atlite's own processing of the same end-stamped data (`_process_influx`, position at -30 min, label h+1, instantaneous temperature at the stamp). On the SYNTHETIC fixture the mean absolute difference is 1.5e-4 (bound 3e-4; the residual is the temperature endpoint mean), and < 1e-5 when temperature cannot differ. The report's own 0.0003 on real data is not reproducible here. | Test only. |
| S17 | SYNTHETIC fixtures | CM SAF-format daily files (int16, fill -999, `lat_bnds`/`lon_bnds`, `record_status` with void and bad_quality steps, 0.05 deg grid, a northern cutoff and a static patch of fill, spanning 31 Jul -> 1 Aug); raw CDS ERA5 solar as NetCDF and as ZIP (instant + accum members), end-stamped, plus a prepared hour-start variant; all stamped `SYNTHETIC`.
